## Never install `@tamagui/*` in this app

bobuttons bundles its own copy of Tamagui inside its built files; this
app's own `package.json` declares no `@tamagui/*` dependency, and must
never add one. Installing a second Tamagui copy alongside the one bobuttons
bundles is exactly how the "can't find Tamagui configuration" runtime crash
happens — even though bobuttons is a single package, a second installed
`@tamagui/core` resolves to a different module instance than the one
`BobuttonsProvider` configured, and Tamagui's runtime can no longer find
its own configuration. Render `<BobuttonsProvider>` alone at the root (see
`App.tsx`); never wrap the tree in a separate `<TamaguiProvider>`.

## Chicago map (Leaflet)

The app displays a Leaflet map centred on Chicago, rendered inside a
`react-native-webview` loaded from a local Android asset
(`file:///android_asset/leaflet/map.html`) - never as inlined
`source={{ html }}`, since an inline document has no base URL for the
relative `<script src="leaflet.js">` / `<link href="leaflet.css">` tags
to resolve against. Map parameters (Chicago's coordinates, the initial
zoom, the OSM tile URL template, the attribution string) live in
`src/map/mapConstants.ts` and are passed into the page as one
JSON-stringified config, never duplicated into `map.html`.

## Jest

This app's `jest.config.js` appends `bobuttons` to the `react-native`
preset's own `transformIgnorePatterns` alternation, because `App.test.tsx`
and `map.test.tsx` render `AppShell` from bobuttons:

```js
module.exports = {
  preset: 'react-native',
  transformIgnorePatterns: [
    'node_modules/(?!((jest-)?react-native|@react-native(-community)?|bobuttons)/)',
  ],
};
```

Without re-including the preset's own alternation, overriding this key
breaks transform handling for `react-native` itself, not just for
bobuttons — bobuttons' build (`dist/index.native.js`) is ESM
(`"type": "module"`), which is why an unmodified Jest config fails with
`SyntaxError: Cannot use import statement outside a module` the moment a
test imports it.

Three test files ship with this app: `__tests__/App.test.tsx` (the
generator's smoke test, kept in its generated shape - it renders through
the real `SafeAreaProvider`, which yields zero children under Jest, so it
asserts nothing about the tree, but it does exercise the
`react-native-webview` mock every test file that reaches that module needs,
since its entry is ESM and the preset does not whitelist it);
`__tests__/map.test.tsx` (the AC-bearing test for the Leaflet map - see
`src/map/`); and `__tests__/dependencies.test.ts` (the installed-tree guard
against a second Tamagui or web copy - see "Never install `@tamagui/*` in
this app" above).

## Prerequisites for building

The JavaScript dependencies were installed when this app was generated
(unless it was generated with `--no-install`, in which case run `npm ci`
first). Building the Android app itself additionally needs, on this
machine:

- JDK 17 or newer (required by Gradle 9.0 and Android Gradle Plugin 8.12).
- The Android SDK, with `platform-tools` installed and `ANDROID_HOME` (or
  `ANDROID_SDK_ROOT`) pointing at it.
- The SDK licences accepted (`sdkmanager --licenses`).
- Network access for the *first* build only - see below.

None of this is installed by the generator; provisioning the Android
toolchain is outside AppGenerator's job.

## Building

```
cd android
./gradlew assembleDebug
```

The debug APK is written to `android/app/build/outputs/apk/debug/`.

**The first build needs network access.** It downloads the Gradle 9.0.0
distribution and the Maven artifacts for the Android Gradle Plugin, Kotlin
and the React Native Android runtime, then compiles native code with the
NDK. None of that is front-loaded by the generator - only the npm/JS
dependencies are. Later builds reuse what was downloaded into `~/.gradle`.

## Running Metro + the app

```
npm start
```

in one terminal (the Metro bundler), and in another:

```
npm run android
```

which builds (if needed) and installs the debug APK onto a connected
device or running emulator.

## Shared debug keystore

This app is signed for debug builds with the standard Android debug
keystore shipped by the React Native template (`android/app/debug.keystore`,
password `android`), not a keystore unique to this app. Two generated apps
whose names collide on the same derived identifier (see below) therefore
cannot be installed side by side on one device. Release signing is out of
scope for the generator.

## Application id

The Android namespace / `applicationId` was derived from this app's name
and is not a placeholder. Apps with different names get different
`applicationId`s; apps whose names differ only in separators (for example
`my-app` and `my.app`) are sanitised to the same identifier and will
collide - this is a documented, deterministic property of the name
sanitisation, not a bug.
